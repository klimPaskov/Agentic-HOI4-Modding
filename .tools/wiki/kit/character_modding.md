What vanilla `common/characters/` contains, counted over 5,409 characters in 232 files (parsed with a script, `instance` blocks included).

- Vanilla uses exactly 11 top-level keys in a character: `name`, `portraits`, `gender`, `advisor`, `country_leader`, `corps_commander`, `field_marshal`, `navy_leader`, `scientist`, `instance` and `allowed_civil_war`. Characters that have each key: `portraits` 4,946, `advisor` 3,732, `name` 3,584, `corps_commander` 624, `country_leader` 558, `instance` 463, `navy_leader` 135, `scientist` 102, `allowed_civil_war` 100, `field_marshal` 99, `gender` 60. The `gender` lines are `female` (40) and `male` (24); none writes `undefined`. [vanilla-confirmed 1.19.4.1] `common/characters/`.
- There are six roles: `country_leader`, `corps_commander`, `field_marshal`, `navy_leader`, `advisor`, `scientist`. There is no air commander role and no operative role in the character files; air appears only as the `air_chief` advisor slot and the `specialization_air` scientist specialization. [vanilla-confirmed 1.19.4.1] `common/characters/`.
- Operatives are created with `create_operative_leader` (country scope), not in character files. The documentation still runs the operative effects and triggers in character scope (`is_operative`, `has_nationality`, `is_operative_captured`, `capture_operative`, `free_operative`, `kill_operative`, `turn_operative`), so an operative is addressed as a character scope even though the wiki intro says operatives are not characters. [docs] `documentation/effects_documentation.md`, `documentation/triggers_documentation.md`
- A character can hold several roles. 417 characters have an `advisor` role together with at least one of `corps_commander`, `field_marshal` or `navy_leader`; 284 of them have both blocks at the top level and the rest get one through an `instance`. 121 characters define no role block at all. [vanilla-confirmed 1.19.4.1] `common/characters/`.
- `allowed_civil_war = { ... }` sits at the top level of 100 characters (116 uses in all) and holds triggers, scripted ones such as `NOR_char_cw_democratic = yes` (`common/characters/NOR.txt`) or plain ones such as `has_government = fascism`. [vanilla-confirmed 1.19.4.1] It decides which side of a civil war keeps the character, with a catch for unit leaders. In a fascist civil war started by `start_civil_war` on NOR, the democratic-only prime minister stayed with NOR, and the two fascist-only characters went to the rebel country. Two characters whose `allowed_civil_war` fails on both sides stayed with NOR. The king and Trotskij, who have unit leader roles (navy leader and corps commander), were listed under both NOR and the rebel country. [game-tested 1.19.4.1] HOI4 Live Tools run, 2026-11-02, start_civil_war on NOR, holder of each character read in game.log right after and one day later. The unit leader roles may be why those two were listed twice, but the logs do not show it, and only one civil war (fascism on NOR) was run.
- `can_be_captured = no` is documented as an optional character key (default yes). See [Captured generals](#captured-generals) under "Unit leaders". [docs] `common/characters/_documentation.md`.

<!-- kit:begin id="char-leader-effects" at="section:using-in-game" -->
Exact behaviour of the character effects this section names. Syntax: [docs] `documentation/effects_documentation.md`; counts: [vanilla-confirmed 1.19.4.1] over `common/`, `events/` and `history/`.

- `recruit_character = id` runs in country scope. All 5,612 vanilla uses sit in 257 files under `history/countries/`; none is anywhere else, and `generate_character` (128 uses) is only in `history/general/`. [vanilla-confirmed 1.19.4.1] `hoi4.exe` contains the text "recruit_character should only happen in game/history files in order to be executed only at game start", and also "cannot be assigned to ... as it is already assigned to ...", so one character belongs to one country at a time. The documentation sets no timing limit, so treat history-only as a convention. Outside history it works at run time: a `recruit_character` in a scripted effect run from the console put the character into the country, and the game printed a load warning for each such line ("recruit_character should only happen in game/history files in order to be executed only at game start"). [game-tested 1.19.4.1] HOI4 Live Tools run, 2026-11-02, scripted effect, game.log and error.log. Do not recruit in events or focuses without testing.
- `promote_character` has a country form (`promote_character = id`, or `{ character = id ideology = x }`) and a character form (`promote_character = yes`, `= ideology`, or `{ ideology = x }`). The ideology is mandatory only when the character has several country leader roles. 376 vanilla uses. [docs]
- `add_country_leader_role = { character = id promote_leader = yes country_leader = { ideology = x expire = "1965.1.1.1" traits = { ... } } }` (`character` is optional in character scope). `hoi4.exe` has the messages "Character already has a country leader role for ideology:" and "Character already has a country leader role with this ideology", so adding a second role for an ideology the character already leads for is refused; check with `has_ideology = x` in character scope first. 898 vanilla uses. [vanilla-confirmed 1.19.4.1] [docs] for syntax. The refusal is real: a second `add_country_leader_role` for `fascism_ideology` logged "Character already has a country leader role for ideology: Fascism" with the file and line, and the rest of the effect kept running. [game-tested 1.19.4.1] HOI4 Live Tools run, 2026-11-02, scripted effect and error.log. The number of roles was not read, and an ideology group name (`fascism`) was replaced by `fascism_ideology` in the test.
- `remove_country_leader_role = { character = id ideology = x }` removes one leader role. 113 vanilla uses.
- `set_character_name` takes the new name, not a character token. Block form: `set_character_name = { character = id name = KEY_OR_TEXT }` in country scope, with `character` dropped inside a character scope; `name` is a localisation key or a literal. Scalar form in character scope: `set_character_name = KEY`. Vanilla passes keys such as `ITA_benito_mussolini_roman_emperor`. 12 vanilla uses.
- `kill_country_leader = yes` (country scope) removes the leader completely and makes the next in line the new party and country leader (42 uses). `retire_country_leader` (163 uses) removes the leader from party leadership and also hands over to the next in line. The documentation matches the wiki's kill/retire split for this pair, but its texts for `kill_ideology_leader` (9 uses) and `retire_ideology_leader` (21 uses) are the other way round, so do not rely on the ideology pair. Prefer `promote_character`, `retire_character` and `remove_country_leader_role`, which name the character.
- `retire_character = id` (country) and `retire = yes` (character) remove the character from the country with all roles; `set_nationality` brings them back. 289 and 41 vanilla uses.
- `set_portraits = { character = id civilian = { large = GFX_x small = GFX_y } army = { ... } }` (country scope; `character` is dropped in character scope). 53 vanilla uses.

<!-- kit:begin id="char-trait-selection-correction" at="section:selection" -->
The parent syntax in the table above differs from the vanilla format. The comment at the top of `common/unit_leader/00_traits.txt` documents it as a block: `parent = { traits = { a b c } num_parents_needed = 1 }`, which can be repeated, plus two shorthands: `any_parent = { a b c }` (one of them is enough) and `all_parents = { a b c }` (every one is needed). Vanilla uses `any_parent` in 41 traits and the block `parent` once (with `num_parents_needed = 2`); `all_parents` and a plain `parent = trait_id` appear nowhere. `hoi4.exe` has the validation message "num_parents_needed is superior to the number of parents". The wiki's `parent = my_trait` with a separate `num_parents_needed` is [unverified]; write the vanilla form. [vanilla-confirmed 1.19.4.1] `common/unit_leader/00_traits.txt`; the message is [unverified] (executable string only).
