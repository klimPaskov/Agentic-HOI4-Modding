# Country activation and deferred setup

Entering another country scope does not rebind ROOT. If a setup helper needs the recipient as ROOT, invoke it from a hidden triggered-only country event received by that country. Regular event targets carry through events fired by the originating effect chain.

## Callback and iterator ROOT contracts

Capture and annex callbacks retain their native ROOT: `on_annex` has the winner as ROOT and the annexed country as FROM, while `on_state_control_changed` has the new controller as ROOT, the old controller as FROM, and the changed state as FROM.FROM.
Trace each callback-to-helper scope chain before changing a receipt read.
When a country helper enters its exact source-state pointer, PREV there is the calling owner, so read that owner's receipt through PREV rather than the callback's ROOT.
Within a state's stored-owner or holder country scope, return explicitly to the state through PREV for state flags.
PREV depends on the actual nesting, and ROOT remains valid wherever the contract explicitly requires it.

In a participant-country iterator reached from a country event, `ROOT` remains that event's original recipient across participant-country and state scope changes.
For targeted decisions, verify the actual callback's `ROOT`/`FROM` contract against installed documentation and a native precedent rather than assuming the owner's country-event contract: in the standard targeted-decision context, `ROOT` is the country taking the decision and `FROM` is its target country or state.
Capture the intended current participant with regular `save_event_target_as = participant` in that participant's country scope before entering state scope, then use `event_target:participant` for helper payer, victim, and target-country inputs and for participant receipt or idempotence flags.
Using an unrelated `ROOT` can misattribute casualties and receipts even when the correct state was selected; retain `ROOT` wherever the documented callback or helper contract requires it.

## Frozen transaction inputs and receipts

For synchronous country transactions that can launch nested helper work, `ROOT` remains the original sender, temporary loop indexes are unscoped, and regular event-target names are shared throughout the effect chain.
Nested transaction setup can overwrite both indexes and named targets, so a regular event target alone is not a frozen transaction input.
Before any helper that can launch nested work, capture the proven source and origin pointers, actor, episode, and receipt identity, and outer row indexes into recipient-owned normal private input fields.
At durable context commit, read those frozen fields and validate real object existence plus exact actor, episode, and receipt identity, rather than trusting overwritten aliases or `scope_exists` on a variable scope.
Restore outer row indexes only from that frozen frame, and clear the private fields on every success or rejection return while preserving the public immediate outputs.

Require matching actor and state nonce mirrors and exact source-state identity before closing a receipt or applying its accounting.
Use actor-owned persistent state pointers for asynchronous local projects and revalidate site identity and current holder at resolution.
Cleanup for a nonexistent or dead actor must not clear another living actor's global selection.
Partition recorded-owner and physical-holder accounting by the state disposition so each amount is debited and credited once even when both pointers identify the same country.
Review matching and stale nonces, distinct and identical owner and holder identities, repeated closure, and dead-actor cleanup along the exact source call chains.

## State-owned cadence and deferred verification

When bounded controller-country callbacks service a STATE-owned mechanic, keep each independent review or growth date persistently on that state and gate advancement on elapsed time.
Controller changes must preserve those dates so cycling controllers or receiving duplicate callbacks cannot accelerate the same mechanic's cadence.
Callback count is not elapsed time.

When a terminal record stops maintenance but an achievement or outcome still needs elapsed-time verification, schedule a one-time callback in the record owner's scope guarded by a persistent due date and a pending receipt consumed before verification.
Preserve the original due date across narrow controller changes, rescheduling only the remaining delay when delivery needs repair.
Revalidate the exact record and eligible actor tag under the existing identity contract, preserving any actor-specific invalidation.
Check early, duplicate, transferred, and stale-actor deliveries without adding a periodic world scan.

## Activation and deferred setup

Give a dormant tag owned land and a valid capital before capital-dependent setup or unit spawning. Use runtime meta construction when the TAG scope must be deferred until activation. For player transfer, queue the delayed recipient event before `change_tag_from`, then make transfer the final effect in that country block so later scheduling does not reuse an invalidated scope. Inject file-scoped duration constants as meta arguments rather than leaving unresolved `@` tokens in generated text.

History grants may run before capitals or other countries are initialized. Preserve local grants and queue dependent scoring or diplomatic refreshes until activation. Test the owned-state capital condition before entering `capital_scope`, since entering an invalid scope to test it can itself fail.

When several hooks request the same full refresh, coalesce requests behind one pending recipient event. Track scheduled delivery separately from pending work if an immediate refresh may consume the work before delivery. Set scheduling state before enqueueing, clear scheduling and pending-work state before dispatch, and retain the explicit immediate-apply path. Check repeated requests, refresh while pending, convergence, and every existing consumer or repair hook.

Exposed database arrays may include a reserved default object. Verify registration order, default-object initialization, and the consuming effect's validity check against installed documentation or direct engine evidence before excluding an entry. Exclude only a confirmed reserved slot and retain dynamic coverage of real entries. Read-only engine inspection is not executed runtime validation.

Use the event owner's mandatory MCP baseline, lifecycle inspection, render, and comparison requirements for these chains. Record exact unavailable-route blockers. Source-only review cannot replace the required evidence.
