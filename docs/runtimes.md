# Agent runtimes

This repository can be opened in more than one coding-agent runtime.
The HOI4 rules themselves are runtime-neutral; only the discovery paths, the subagent registry, and MCP registration differ per runtime.

Read this page before adapting a runtime-specific file, and keep one instruction authority instead of maintaining competing copies.

## Instruction files

Each runtime loads its project instructions from a different file name.

| Runtime | Project instruction file | Discovery |
| --- | --- | --- |
| Codex | `AGENTS.md` | Project root, bounded by the configured project-document byte budget. |
| Claude Code | `CLAUDE.md` | Project root. `@path` import lines are interpreted. |
| DSH | `AGENTS.md` and `CLAUDE.md` | Every directory from the project root down to the working directory, broad-to-specific, plus the user-global `$DSH_HOME/AGENTS.md`. |
| Cursor | `AGENTS.md` | Declared in `.cursor/settings.json`. |
| Qoder | `AGENTS.md` | Declared in `.qoder/settings.json`. |
| OpenCode | `AGENTS.md` | Declared in `.opencode/settings.json` and the root `opencode.json`. |

Consequences worth knowing before you install instructions:

- DSH does **not** interpret `@path` import lines. A `CLAUDE.md` that only imports `AGENTS.md` contributes nothing in DSH.
- DSH collapses sibling files in one directory only when their content is byte-identical after trimming surrounding whitespace. Different content from the pair is loaded in full, twice, as two competing rule sets.
- DSH caps the whole rendered instruction baseline. The base bundle and the shipped session preset both set 65,536 bytes, and a single source file above 1 MiB is not loaded at all. These instruction files are large, so install the one file the runtime needs instead of both, and split rarely used detail into skills or `docs/` pages that the agent reads on demand.
- DSH drops broader files whole before it truncates the most specific one, and it reports the omission in a visible `Workspace instruction budget` notice. With both instruction files installed, the broader `AGENTS.md` is dropped and any rule unique to it is lost rather than reconciled, while a source file large enough to exceed the cap alone is truncated instead. A truncated instruction file is a real loss of rules, not a cosmetic warning.
- DSH finds the project root by the nearest ancestor containing `.git`, and injects the chain as ordinary conversation content. Without a `.git` marker, discovery falls back to the working directory and instructions above it stay invisible.
- DSH loads `AGENTS.md` and `CLAUDE.md` as two independent candidates, so `CLAUDE.md` is read even when no `AGENTS.md` exists.
- Cursor, Qoder, and OpenCode read the file named in their own settings. Renaming the project instructions without updating those settings silently removes all project rules.
- The installers ship `AGENTS_template.md` for `AGENTS.md` and `CLAUDE_template.md` for `CLAUDE.md`. Both templates are complete instruction files, so install the one the target runtime actually loads.
- DSH and Claude Code both accept local overlays: `CLAUDE.local.md` and `AGENTS.local.md`. Keep machine-local paths, credentials, and personal preferences there, and keep them out of Git.

## Skills

All runtimes read the same skill library.

| Runtime | Scanned skill roots |
| --- | --- |
| DSH | `<project_root>/.dsh/skills`, `<project_root>/.agents/skills`, then configured, user, and bundled roots. |
| Codex, Claude Code, Cursor, Qoder, OpenCode | `.agents/skills/<skill-name>/SKILL.md` as the repository convention. |

A skill is `<name>/SKILL.md` or a flat `<name>.md` at the top of a scanned root; nested `SKILL.md` files below the first level are not discovered.
Frontmatter requires `name` and `description`; `name` must be kebab-case and match the bundle or file name.
DSH additionally accepts an optional `whenToUse` string, and reads `metadata`, `disable-model-invocation`, and `user-invocable` as optional keys. It rejects the camel-case spellings of the two invocation keys with an explicit warning instead of ignoring them.
A skill with missing or invalid frontmatter is skipped with a warning rather than surfaced as broken, so a skill that does not appear in the catalog usually has a frontmatter problem.

## Subagents

The canonical authoring source is `.codex/agents/*.toml`.
Only runtimes with a project agent registry receive generated projections of it.

| Runtime | Registry | Generated by |
| --- | --- | --- |
| Codex | `.codex/config.toml` `[agents.*]` rows pointing at `.codex/agents/*.toml` | Canonical source; hand-authored. |
| Claude Code | `.claude/agents/<kebab-name>.md` | `python .tools/sync/sync_claude_agents.py` |
| Cursor | `.cursor/agents/<kebab-name>.md` | `python .tools/sync/sync_cursor_agents.py` |
| Qoder | `.qoder/agents/<kebab-name>.md` | `python .tools/sync/sync_qoder_agents.py` |
| OpenCode | `.opencode/agent/<kebab-name>.md` | `python .tools/sync/sync_opencode_agents.py` |
| DSH | None | Not applicable. |

Run every synchronizer after a canonical TOML change, then rerun each with `--check` as the drift gate.
Generated projections are tracked so a fresh checkout works immediately, but they are artefacts: never hand-edit them, and never treat them as authority.

DSH is the exception.
It ships no project-local registry of named subagents and does not read `.codex/agents/*.toml`, so no naming, description, sandbox, or model field from a TOML reaches a DSH subagent.
In DSH the canonical snake_case identifiers remain routing and ownership contracts, and the parent must write the role boundary, allowed files, forbidden files, ownership limits, evidence format, and handoff path into the delegated prompt itself.
Because no definition supplies the model, confirm the child route explicitly when the task depends on a particular model or reasoning effort, and record the route that was actually used in the handoff.

## MCP registration

Each runtime owns its own MCP registration.
Do not copy one runtime's approval, sandbox, absolute-path, environment, or tool-allowlist keys into another runtime unless that runtime has a verified equivalent.

| Runtime | Registration file | Shape |
| --- | --- | --- |
| Codex | `.codex/config.toml` | `[mcp_servers.<name>]` with `command`, optional `cwd`, timeouts, and approval mode. |
| Claude Code | `.mcp.json` | `{"mcpServers": {"<name>": {"type": "stdio", "command": "...", "args": [], "env": {}}}}`. Requires a one-time project trust decision before the server starts. |
| Cursor | `.cursor/mcp.json` | `{"mcpServers": {"<name>": {"command": "...", "args": []}}}`. |
| Qoder | `.qoder/mcp.json` | `{"mcpServers": {"<name>": {"command": "...", "args": []}}}`. |
| OpenCode | `.opencode/mcp.json` | `{"mcpServers": {"<name>": {"command": ["..."]}}}`. |
| DSH | `$DSH_HOME/profiles/<profile>/cordis.patch.yml` | A loader patch row inserting `@deepseek-ai/dsh-mcp-client`, one row per server. |

On Windows every project-scoped file above points at the same `hoi4-agent-tools.cmd` wrapper installed by `.tools/mcp/bootstrap_hoi4_agent_tools.py`.
Those `.cmd` registrations are Windows-only, and no runtime may substitute an unverified entry point for them.

DSH has no project-scoped MCP file.
Its servers are deployment configuration, not repository content, so the registration lives in the active profile and stays out of Git.
One row per server, and the profile must also depend on the MCP client package:

```yaml
- id: mcp-hoi4-agent-tools
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: hoi4_agent_tools
    transport: stdio
    command: hoi4-agent-tools.cmd
    cwd: "C:\\Users\\<you>\\OneDrive\\Documents\\Paradox Interactive\\Hearts of Iron IV\\mod\\<your_mod>"
    failOnStartupError: true
```

DSH namespaces every bridged tool as `mcp__<serverName>__<rawToolName>`, so the HOI4 routes appear in a session as `mcp__hoi4_agent_tools__hoi4_focus_inspect` and similar.
The server namespace is local configuration rather than the remote server's own name, and a `serverName` may only contain letters, digits, underscore, and hyphen.

The MCP evidence rules in the project instructions do not change per runtime: an in-scope focus tree, event chain, technology or doctrine tree, weighted-logic system, scripted GUI, or map surface requires the matching inspect, render, lint, compare, evaluate, or rewrite route before and after the change, and an unavailable route is a recorded blocker rather than a reason to substitute source-only review.

## Model selection

Model and reasoning-effort selection is deployment configuration, not repository content.
Keep model identifiers, provider routes, and credential names out of shared instruction files.
The optional per-project subagent model policy belongs in the profile configuration of the runtime in use, and a runtime that composes subagents from the prompt alone must have its route stated explicitly per delegation.
